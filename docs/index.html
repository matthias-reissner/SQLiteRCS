Diese Beispiele laufen mit der installierten Erweiterung. Der Browser-Playground darunter ist davon unabhängig und simuliert den Ablauf.

01 Archiv anlegen 
CREATE TABLE documents (
  id INTEGER PRIMARY KEY,
  history TEXT NOT NULL DEFAULT ''
);

INSERT INTO documents (history)
VALUES (rcs_checkin(
  '',
  'Erste Zeile' || char(10),
  'Erstellung'
));
02 Branch & Check-in 
UPDATE documents
SET history = rcs_create_branch(
  history, 'feature', '1.1'
)
WHERE id = 1;

UPDATE documents
SET history = rcs_branch_checkin(
  history, 'feature',
  'Erste Zeile' || char(10) || 'Branch' || char(10),
  'Feature begonnen'
)
WHERE id = 1;
03 Revisionen abfragen 
SELECT rcs_head(history),
       rcs_checkout(history, 'feature'),
       rcs_diff(history, '1.1', 'feature')
FROM documents
WHERE id = 1;

SELECT rcs_revisions(history)
FROM documents
WHERE id = 1;
04 Drei-Wege-Merge 
SELECT rcs_merge(
  history, '1.1', 'feature', 'stable'
)
FROM documents
WHERE id = 1;

In wenigen Schritten startklar

Baue die
Erweiterung.

SQLiteRCS wird als loadable extension gebaut und kann mit SQLite-Anwendungen verwendet werden, die Erweiterungen laden dürfen.

Quellcode auf GitHub ↗
01

Voraussetzungen

C-Compiler, Python 3 und SQLite-Entwicklungsheader (`sqlite3.h`, `sqlite3ext.h`).

02

Erweiterung bauen

# Linux / macOS
make

# Windows: x64 Developer Prompt
set SQLITE_INCLUDE_DIR=C:\path\to\sqlite
build.bat
03

Tests ausführen

SQLITERCS_EXTENSION=./sqlitercs.so make test

# Windows
set SQLITERCS_EXTENSION=sqlitercs.dll
python -m unittest discover -s tests -v
04

Extension laden

conn.enable_load_extension(True)
conn.load_extension("sqlitercs")

SQLiteRCS unterstützt trunk- und verschachtelte Branch-Revisionen, Tags, mehrteilige Diff-Hunks, Drei-Wege-Merges und den Import/Export textueller RCS-Archive.
Inhalte sind UTF-8-Text, keine Binärdaten; nicht-leere Inhalte enden mit einem Zeilenumbruch. Importierte Zugriffslisten und Sperren werden normalisiert, aber nicht erhalten oder durchgesetzt.
